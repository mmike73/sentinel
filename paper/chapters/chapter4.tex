\section{Implementarea programului eBPF}
\label{sec:ebpf_impl}

\par Programul eBPF (\texttt{tracer.bpf.c}, 157 de linii) este compilat cu comanda:

\begin{verbatim}
clang -target bpf -O2 -g -D__TARGET_ARCH_x86 \
  -I/usr/include -I/usr/include/x86_64-linux-gnu \
  -c tracer.bpf.c -o tracer.bpf.o
\end{verbatim}

\par Contractul de date dintre spațiul kernel și cel utilizator este definit de structura \texttt{event}, transmisă prin ring buffer. Dimensiunile fixe (\texttt{comm[16]}, \texttt{fname[128]}) sunt impuse de verificatorul eBPF, care respinge orice alocare dinamică în heap-ul kernel:

\begin{lstlisting}[style=cstyle,caption={Structura evenimentului și hărțile eBPF din \texttt{tracer.bpf.c}}]
struct event {
    __u64 ts_ns;       /* bpf_ktime_get_ns() */
    __u32 pid;
    __u32 uid;
    __u32 syscall_nr;
    char  comm[16];
    char  fname[128];
};

/* Ring buffer de 64 MiB: zero-copy, lockless, per-CPU ordering */
struct { __uint(type, BPF_MAP_TYPE_RINGBUF);
         __uint(max_entries, 64 * 1024 * 1024); } events SEC(".maps");

/* Contor de evenimente pierdute (per-CPU, fara lock) */
struct { __uint(type, BPF_MAP_TYPE_PERCPU_ARRAY);
         __uint(max_entries, 1);
         __type(key, __u32); __type(value, __u64);
} drop_count SEC(".maps");
\end{lstlisting}

\par Flag-ul \texttt{-O2} este esențial din două motive: verificatorul eBPF impune o limită de 1 milion de instrucțiuni per execuție și respinge programele cu structuri de control prea complexe; în plus, backend-ul LLVM pentru arhitectura BPF necesită un arbore de sintaxă optimizat pentru a emite \textit{opcodes} BPF valide --- codul neoptimizat (\texttt{-O0}) generează frecvent accesări de memorie pe care Verificatorul le respinge ca nesigure.

\par O decizie de implementare importantă privește extragerea sigură a căilor absolute ale fișierelor. Handler-ul \texttt{submit\_event\_with\_path} utilizează secvența:

\begin{verbatim}
struct pt_regs *inner = (struct pt_regs *)PT_REGS_PARM1(ctx);
unsigned long fname_uptr = 0;
bpf_probe_read_kernel(&fname_uptr, sizeof(fname_uptr), &inner->rsi);
bpf_probe_read_user_str(e->fname, sizeof(e->fname),
                        (const char *)fname_uptr);
\end{verbatim}

\par Funcția \texttt{submit\_event} encapsulează întregul protocol de emitere: verificarea blacklist-ului, rezervarea zero-copy a unui slot în ring buffer și tratamentul atomic al eșecului de rezervare:

\begin{lstlisting}[style=cstyle,caption={Funcția \texttt{submit\_event}: rezervare ring buffer și contorizare drop-uri}]
static __always_inline int submit_event(__u32 syscall_nr)
{
    __u32 pid = bpf_get_current_pid_tgid() >> 32;
    if (bpf_map_lookup_elem(&pid_blacklist, &pid))
        return 0;

    struct event *e = bpf_ringbuf_reserve(&events, sizeof(*e), 0);
    if (!e) {
        __u32 key = 0;
        __u64 *cnt = bpf_map_lookup_elem(&drop_count, &key);
        if (cnt) __sync_fetch_and_add(cnt, 1);
        return 0;
    }
    e->ts_ns      = bpf_ktime_get_ns();
    e->pid        = pid;
    e->uid        = bpf_get_current_uid_gid() & 0xFFFFFFFF;
    e->syscall_nr = syscall_nr;
    bpf_get_current_comm(&e->comm, sizeof(e->comm));
    e->fname[0]   = '\0';
    bpf_ringbuf_submit(e, 0);
    return 0;
}
\end{lstlisting}

\par Kprobe-urile sunt atașate la wrapper-urile \texttt{\_\_x64\_sys\_*} care primesc un singur argument --- un pointer la structura \texttt{pt\_regs} cu argumentele originale ale syscall-ului. Accesul direct la argumentele syscall-ului necesită dereferențierea unui nivel suplimentar de \texttt{pt\_regs} (\textit{inner regs}), o idiomă documentată în \cite{Rice2023} și necesară pentru compatibilitatea cu versiunile kernel $\geq 4.17$ pe x86\_64.

\par Mecanismul de drop count este implementat cu \texttt{\_\_sync\_fetch\_and\_add}, operație atomică per-CPU: când ring buffer-ul este plin și rezervarea eșuează, contorul de drop al CPU-ului curent este incrementat. Un goroutine din daemon citește periodic contoarele și loghează creșterile.


\section{Implementarea daemonului Go}
\label{sec:daemon_impl}

\par Daemonul Go (\texttt{daemon/main.go}, 497 de linii) orchestrează pipeline-ul de detecție. La pornire, daemonul:

\begin{enumerate}
    \item Ridică limita \texttt{RLIMIT\_MEMLOCK} prin \texttt{rlimit.RemoveMemlock()}, necesară pentru alocarea ring buffer-ului de 64 MiB.
    \item Blochează thread-ul OS cu \texttt{runtime.LockOSThread()} --- această operație este mandatorie, deoarece anumite apeluri de sistem eBPF și asocieri de namespace-uri sunt dependente de contextul specific al thread-ului care le inițiază \cite{CiliumEBPF}.
    \item Încarcă colecția eBPF din fișierul \texttt{.bpf.o}, atașează kprobe-urile și deschide reader-ul de ring buffer.
    \item Inserează propriul PID în \texttt{pid\_blacklist} pentru a preveni buclele de auto-instrumentare.
\end{enumerate}

\par Inițializarea reader-ului și deschiderea bazei de date cu instrucțiune pregătită se realizează astfel:

\begin{lstlisting}[style=gostyle,caption={Inițializarea ring buffer reader și a instrcțiunii de inserție SQLite}]
rb, err := ringbuf.NewReader(coll.Maps["events"])
if err != nil { log.Fatalf("ringbuf.NewReader: %v", err) }
defer rb.Close()

db, _ := sql.Open("sqlite3",
    *dbPath+"?_journal_mode=WAL&_synchronous=NORMAL&_busy_timeout=5000")

stmt, _ := db.Prepare(`INSERT INTO events
    (alert_type, score, state, pid, comm, timestamp, detail)
    VALUES (?, ?, ?, ?, ?, datetime('now'), ?)`)
\end{lstlisting}

\par Bucla principală citește din ring buffer în mod blocant, parsează evenimentele prin \texttt{binary.Read} și aplică cele trei etape de scoring:

\begin{lstlisting}[style=gostyle,caption={Bucla principală de procesare a evenimentelor din ring buffer}]
for {
    record, err := rb.Read()  // blocat pana la urmatorul eveniment
    if err != nil { break }

    var e bpfEvent
    binary.Read(bytes.NewReader(record.RawSample), binary.LittleEndian, &e)

    comm  := string(bytes.TrimRight(e.Comm[:],  "\x00"))
    fname := string(bytes.TrimRight(e.Fname[:], "\x00"))

    score := staticScore(e.SyscallNr, e.Uid)
    aType := alertType(e.SyscallNr)

    if bScore, bType, ok := bursts.check(e.Pid, e.SyscallNr, 5, 3e9, 10e9); ok {
        score, aType = bScore, bType
    } else if pScore, pType, ok := pathAlert(e.SyscallNr, fname); ok {
        score, aType = pScore, pType
    }

    state  := scoreToState(score)
    detail, _ := json.Marshal(map[string]interface{}{
        "syscall_nr": e.SyscallNr, "comm": comm, "score": score,
        "state": state, "source": "kprobe",
    })
    stmt.Exec(aType, score, state, e.Pid, comm, string(detail))
}
\end{lstlisting}

\par Operațiunea de inserare în SQLite utilizează o instrucțiune pregătită (\textit{prepared statement}) pentru a elimina overhead-ul de parsare SQL per eveniment.

\par Detectarea rafale (\texttt{burstTracker}) menține o mapă \texttt{windows[key][]int64} cu timestamp-urile apelurilor dintr-o fereastră glisantă. Cheia de burst este:

\begin{equation}
    \text{key}(pid, nr) = (\text{pid} \ll 32) \mid (nr \ll 16) \mid (\text{start\_time} \mathrel{\&} 0\text{xFFFF})
    \label{eq:burst_key}
\end{equation}

\par Incluzând \texttt{start\_time} (câmpul 22 din \texttt{/proc/\{pid\}/stat}, exprimat în \textit{ticks} de ceas) în cheie, sistemul distinge între procese diferite care rulează cu același PID pe parcursul testelor --- o situație frecventă în suita de atacuri, unde procesele au durată scurtă de viață. Utilizarea exclusivă a ultimilor 16 biți din \texttt{start\_time} introduce o probabilitate de coliziune matematic neglijabilă ($\approx 1/65536$), un compromis excelent între precizia detecției și amprenta de memorie.

\par Funcția \texttt{burstKey} codifică identitatea unui proces în 64 de biți, incluzând \texttt{start\_time} din \texttt{/proc/\{pid\}/stat} pentru a distinge procese care reutilizeaza PID-uri:

\begin{lstlisting}[style=gostyle,caption={Cheia de burst și logica ferestrei glisante}]
func burstKey(pid, nr uint32) uint64 {
    st := pidStartTime(pid)  // campul 22 din /proc/{pid}/stat (ticks)
    return (uint64(pid) << 32) | (uint64(nr) << 16) | (st & 0xFFFF)
}

func (b *burstTracker) check(pid, nr uint32,
    threshold int, windowNs, cooldownNs int64) (float64, string, bool) {
    k   := burstKey(pid, nr)
    now := time.Now().UnixNano()
    b.mu.Lock(); defer b.mu.Unlock()
    // retine doar timestamp-urile din fereastra activa
    pruned := b.windows[k][:0]
    for _, t := range b.windows[k] {
        if t >= now-windowNs { pruned = append(pruned, t) }
    }
    b.windows[k] = append(pruned, now)
    if len(b.windows[k]) < threshold { return 0, "", false }
    if last, ok := b.lastFire[k]; ok && now-last < cooldownNs {
        return 0, "", false
    }
    b.lastFire[k] = now
    if nr == 41 || nr == 42 { return 75.0, "NetworkAnomaly", true }
    if nr == 56              { return 35.0, "SyscallAnomaly",  true }
    return 0, "", false
}
\end{lstlisting}

\par Dacă scorerul ML este activ, scorul static este rafinat asincron prin amestecul ponderat cu scorul Isolation Forest. Ponderea ML este invers proporțională cu certitudinea scorului static --- syscall-urile cu risc ridicat (ex. \texttt{init\_module}, $w=95$) necesită corecție minimă, în timp ce syscall-urile ambigue (ex. \texttt{write}, $w=5$) beneficiază cel mai mult de contextul furnizat de model:

func scorerWeight(nr uint32) float64 {

    switch {
    case w >= 85: return 0.1  // init_module, finit_module
    case w >= 60: return 0.2
    case w >= 30: return 0.5
    default:      return 0.7  // write, socket, clone
    }
}

// Goroutine asincron --- nu blocheaza bucla principala:

\section{Implementarea scorerului ML}
\label{sec:scorer_impl}

\par Scorerul ML (\texttt{scorer/isolation\_forest.py}, 195 de linii) expune un API FastAPI cu trei endpoint-uri: \texttt{GET /health}, \texttt{POST /score} și \texttt{POST /model/train}. Modelul este încărcat \textit{lazy} la primul apel \texttt{/score}, eliminând latența de inițializare la pornirea serviciului.

\par Faza de inginerie a caracteristicilor (\textit{feature engineering}) transformă telemetria brută într-un vector de 26 de trăsături. Primele 21 constituie un encoding one-hot al syscall-ului (câte un bit per syscall monitorizat, conform indexului \texttt{SYSCALL\_INDEX}). Caracteristicile suplimentare sunt:

\begin{itemize}
    \item $v_{21}$: flag binar $\mathbb{1}[uid = 0]$ --- capturează comportamentul proceselor root.
    \item $v_{22}$: ponderea de risc normalizată $w_{nr}/100$ --- injectează cunoașterea a priori a riscului syscall-ului în algoritmul nesupervizat. Isolation Forest nu poate distinge semantic între un apel inofensiv și unul critic; adăugarea acestei greutăți forțează algoritmul să izoleze spațial evenimentele inerent periculoase.
    \item $v_{23}$: ora din zi normalizată $h/23$ --- capturează activitate nocturnă atipică.
    \item $v_{24}$: flag weekend $\mathbb{1}[\text{weekday} \geq 5]$.
    \item $v_{25}$: $\log_{10}(\text{pid})/6$ --- diferențiază procesele de sistem (PID mic) de procesele spațiului utilizator.
\end{itemize}

\par Implementarea funcției de extragere a caracteristicilor reflectă direct taxonomia de mai sus:

\begin{lstlisting}[style=pythonstyle,caption={Funcția \texttt{event\_to\_vector}: construirea vectorului de 26 de trăsături}]
SYSCALL_INDEX = {
    1:0, 9:1, 10:2, 41:3, 42:4, 49:5, 56:6, 59:7,
    62:8, 101:9, 105:11, 126:13, 175:14, 313:18, ...
}

def event_to_vector(event: dict) -> np.ndarray:
    v  = np.zeros(26, dtype=np.float32)
    nr = event.get("syscall_nr", 0)
    idx = SYSCALL_INDEX.get(nr, -1)
    if idx >= 0:
        v[idx] = 1.0                           # one-hot syscall (v0..v20)
    v[21] = 1.0 if event.get("uid", 1) == 0 else 0.0
    v[22] = RISK_WEIGHTS.get(nr, 5) / 100.0   # cunostinta a priori de risc
    dt   = datetime.fromisoformat(event.get("timestamp", "").replace("Z", "+00:00"))
    v[23] = dt.hour / 23.0
    v[24] = 1.0 if dt.weekday() >= 5 else 0.0
    v[25] = math.log10(max(event.get("pid", 1), 1)) / 6.0
    return v
\end{lstlisting}

\par Modelul Isolation Forest este antrenat pe evenimentele cu scor static $< 30$ din baza de date (care reprezintă comportamentul de bază), cu parametrii $n\_estimators=200$ și $contamination=0.01$. Vectorii sunt standardizați prin \texttt{StandardScaler} \cite{Pedregosa2011} înaintea antrenării, iar scalarea este aplicată identic la inferență, utilizând parametrii din faza de antrenament. Modelul antrenat este persistat prin \texttt{joblib} și poate fi reantrenat cu date actualizate prin \texttt{POST /model/train} fără a opri serviciul.

\par Conversia scorului brut IF (valoarea \texttt{decision\_function}, negativă pentru anomalii, pozitivă pentru puncte normale) în scor de amenințare pe scala 0--100 utilizează transformarea sigmoidă cu coeficientul de creștere 25, care asigură o tranziție rapidă (abruptă) între stările benigne și maligne --- formula~\ref{eq:sigmoid_transform} din Capitolul~\ref{chap:ch2}. Un punct cu \texttt{raw\_score} $= -0.1$ (ușor anormal) obține \texttt{threat\_score} $\approx 92$, în timp ce un punct cu \texttt{raw\_score} $= 0.1$ (ușor normal) obține \texttt{threat\_score} $\approx 8$.

\par Întregul pipeline de inferență este expus prin endpoint-ul \texttt{POST /score}. Modelul este încărcat \textit{lazy} la primul apel, aplicând același \texttt{StandardScaler} din faza de antrenament:

\begin{lstlisting}[style=pythonstyle,caption={Transformarea sigmoidă și endpoint-ul \texttt{/score}}]
def raw_to_threat_score(raw: float) -> float:
    prob = 1.0 / (1.0 + math.exp(-25.0 * (-raw)))
    return round(min(max(prob * 100.0, 0.0), 100.0), 2)

@app.post("/score")
def score(event: EventRequest):
    b      = get_bundle()                           # incarcare lazy
    vec    = event_to_vector(event.model_dump()).reshape(1, -1)
    scaled = b.scaler.transform(vec)                # acelasi scaler din train
    raw    = b.model.decision_function(scaled)[0]
    threat = raw_to_threat_score(raw)
    return {
        "threat_score": threat,
        "state":        score_to_state(threat),
        "if_raw":       round(raw, 6),
    }
\end{lstlisting}


\section{Implementarea managerului de carantinare}
\label{sec:quarantine_impl}

\par Managerul de carantinare (\texttt{quarantine/main.go}, 306 de linii) validează la pornire disponibilitatea cgroup v2 prin verificarea magic number-ului sistemului de fișiere \texttt{/sys/fs/cgroup} (\texttt{0x63677270} = ``cgrp'' în ASCII) și prezența controllerelor \texttt{cpu} și \texttt{memory} în \texttt{/sys/fs/cgroup/cgroup.controllers}. Această verificare este esențială: pe sisteme cu cgroup v1 sau cgroup v2 fără controllerele activate, acțiunile de carantinare ar eșua silențios.

\begin{lstlisting}[style=gostyle,caption={Validarea cgroup v2 la pornirea managerului de carantinare}]
func validateCgroupV2() {
    const cgroup2Magic = 0x63677270  // "cgrp" ASCII
    var st syscall.Statfs_t
    if err := syscall.Statfs("/sys/fs/cgroup", &st); err != nil {
        log.Fatalf("FATAL: cannot stat /sys/fs/cgroup: %v", err)
    }
    if st.Type != cgroup2Magic {
        log.Fatalf("FATAL: cgroup v2 not found (magic=0x%x)", st.Type)
    }
    data, _ := os.ReadFile("/sys/fs/cgroup/cgroup.controllers")
    for _, ctrl := range []string{"cpu", "memory"} {
        if !strings.Contains(string(data), ctrl) {
            log.Fatalf("FATAL: cgroup v2 controller %q not available", ctrl)
        }
    }
}
\end{lstlisting}

\par Acțiunile de izolare sunt implementate pe trei niveluri de asprime:

\begin{itemize}
    \item \textbf{THROTTLE}: Creează cgroup \texttt{/sys/fs/cgroup/sentinel/quarantine\_\{pid\}} prin \texttt{os.MkdirAll}, scrie PID-ul procesului în \texttt{cgroup.procs} și scrie \texttt{"10000 100000"} în \texttt{cpu.max}. Această configurare permite procesului să utilizeze 10000 microsecunde din fiecare perioadă de 100000 microsecunde, echivalent cu 10\% CPU --- suficient pentru a sugruma operațiunile intensive (ex. \textit{cryptojacking}), fără a opri complet procesul.
    \item \textbf{ISOLATE}: Creează cgroup, scrie limita de memorie de $256 \times 2^{20}$ octeți în \texttt{memory.max}, apoi aplică regulile nftables. Valoarea de 256 MiB a fost aleasă ca suficientă pentru a permite terminarea normală a procesului, dar insuficientă pentru exfiltrarea unor volume mari de date în memorie. Izolarea de rețea utilizează inodul cgroup-ului ca identificator de filtrare în nftables, evitând necesitatea de network namespaces (care nu pot fi aplicate unui proces deja în execuție fără cooperarea sa).
    \item \textbf{FREEZE}: Trimite \texttt{SIGSTOP} procesului (oprire imediată, indiferent de starea actuală), creează cgroup-ul și scrie \texttt{"1"} în \texttt{cgroup.freeze}. Combinația SIGSTOP + \texttt{cgroup.freeze} este critică: chiar dacă un atacator extern ar încerca să reia procesul printr-un semnal \texttt{SIGCONT}, limitarea impusă la nivel de kernel de cgroup previne planificarea (\textit{scheduling}) procesului de către procesor.
\end{itemize}

\par Implementarea concretă a celor două acțiuni extreme ilustrează strategia de containment în profunzime:

\begin{lstlisting}[style=gostyle,caption={Implementarea acțiunilor THROTTLE și FREEZE}]
func createCgroupThrottle(pid int, quota, period string) (string, error) {
    path, _ := createCgroupBase(pid)
    // 10000/100000 = 10% CPU; procesul ruleaza dar nu poate satura CPU-ul
    os.WriteFile(filepath.Join(path, "cpu.max"),
        []byte(quota+" "+period), 0644)
    return path, nil
}

func freezeProcess(pid int, cgPath string) error {
    // SIGSTOP: oprire imediata, inaintea scrieri in cgroup
    syscall.Kill(pid, syscall.SIGSTOP)
    // cgroup.freeze: previne planificarea chiar daca SIGCONT este trimis extern
    os.WriteFile(filepath.Join(cgPath, "cgroup.freeze"), []byte("1"), 0644)
    return nil
}
\end{lstlisting}

\par Izolarea de rețea pentru starea ISOLATE utilizează inodul cgroup-ului ca identificator de filtrare în nftables. Inodul se obține prin \texttt{syscall.Stat} pe calea cgroup-ului; nftables suportă filtrarea \texttt{meta cgroup} prin inod în kernel $\geq 5.10$. Această abordare este net superioară izolării prin \textit{network namespaces}, deoarece poate fi aplicată ``la cald'', fără a necesita repornirea sau cooperarea procesului malițios.

\par Implementarea filtrării de rețea prin inod cgroup este net superioară abordărilor bazate pe PID sau IP, deoarece inodul este stabil pe durata vieții cgroup-ului și nu poate fi falsificat de procesul izolat:

\begin{lstlisting}[style=gostyle,caption={Izolarea de rețea via inod cgroup și nftables (\texttt{meta cgroup})}]
func isolateNetwork(pid int) error {
    cgPath := fmt.Sprintf("/sys/fs/cgroup/sentinel/quarantine_%d", pid)
    var st syscall.Stat_t
    syscall.Stat(cgPath, &st)
    cgID := fmt.Sprintf("%d", st.Ino)  // inodul cgroup = selector nftables

    exec.Command("nft", "add", "table", "inet", "sentinel_quarantine").Run()
    exec.Command("nft", "add", "chain", "inet", "sentinel_quarantine", "output",
        "{ type filter hook output priority 0; policy accept; }").Run()
    exec.Command("nft", "add", "rule", "inet", "sentinel_quarantine",
        "output", "meta", "cgroup", cgID, "drop").Run()
    exec.Command("nft", "add", "rule", "inet", "sentinel_quarantine",
        "input", "meta", "cgroup", cgID, "drop").Run()
    return nil
}
\end{lstlisting}

\subsection{Metodologia de testare}
\label{subsec:test_method}

\par Fiecare scenariu de atac este definit printr-un fișier \texttt{attack.toml} cu patru câmpuri: \texttt{id}, \texttt{name}, \texttt{alert\_type} (tipul de alertă așteptat) și \texttt{expected\_state} (starea minimă așteptată). Scriptul \texttt{run.sh} corespunzător execută atacul propriu-zis.

\par Orchestratorul Python \texttt{run\_sentinel.py} automatizează ciclul de testare, garantând izolarea mediului între teste prin golirea jurnalurilor WAL și restaurarea bazei de date la starea de zero:

\begin{enumerate}
    \item Resetare baza de date (\texttt{DELETE FROM events; PRAGMA wal\_checkpoint}).
    \item Execuție \texttt{run.sh} în mașina virtuală prin \texttt{vagrant ssh}.
    \item Așteptare flux de evenimente ($t_{sleep}$ configurabil per scenariu).
    \item Extragere snapshot baza de date din VM prin SCP.
    \item Verificare: există cel puțin un eveniment kprobe (nu sintetic) cu tipul și scorul corecte?
\end{enumerate}

\par Un test trece dacă și numai dacă există cel puțin un eveniment cu sursă \texttt{"kprobe"} (câmpul \texttt{detail.source}) cu \texttt{alert\_type} corespunzător și \texttt{score} $\geq$ pragul minim. Cerința de evenimente reale (kprobe) distinge testele cu detecție reală de eventualele injecții sintetice de testare.

\section{Clasificarea și descrierea teoretică a suitei de atacuri}
\label{sec:attack_classification}

\par Suita de 20 de scenarii de atac utilizată pentru validarea sistemului Sentinel a fost concepută pentru a acoperi exhaustiv tehnicile documentate în matricea MITRE ATT\&CK pentru Linux \cite{MITRE_ATTCK}. Pentru claritate arhitecturală, atacurile au fost grupate în șapte categorii fundamentale, acompaniate de secvențele de cod care declanșează anomaliile vizate.

\subsection{Rootkit-uri și persistență la nivel de nucleu (Module LKM)}
\label{subsec:attack_lkm}

\par Această categorie vizează compromiterea directă a spațiului privilegiat prin încărcarea unor module malițioase (\textit{Loadable Kernel Modules}).

\par \textbf{REP-01 (Diamorphine Rootkit):} Simulează mecanismul clasic de instalare a unui rootkit compilat pe disc. Utilizează utilitarul \texttt{insmod}, care invocă în fundal apelul \texttt{init\_module}. Sonda Sentinel nu analizează codul rootkit-ului, ci interceptează încărcătorul în sine:

\begin{lstlisting}[style=cstyle,caption={REP-01: Modul de kernel inofensiv pentru declanșarea intercepției LKM}]
static int __init harmless_kernel_module_init(void) {
    printk(KERN_INFO "harmless_kernel_module: incarcat\n");
    return 0; /* Kprobe-ul este declansat la intrarea in sys_init_module */
}
module_init(harmless_kernel_module_init);
module_exit(harmless_kernel_module_exit);
MODULE_LICENSE("GPL");
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{init\_module} (syscall 175) prin kprobe $\rightarrow$ contor \texttt{KernelModuleLoad} $\uparrow$ $\rightarrow$ scor $\approx 90$ $\rightarrow$ FREEZE.}

\par \textbf{REP-17 (Persistență prin \texttt{finit\_module}):} O tehnică de evaziune ce permite încărcarea unui modul de kernel direct dintr-un descriptor de fișier, fără a lăsa urme pe disc. Scenariul folosește un script Python pentru a apela direct funcția C prin \texttt{ctypes}:

\begin{lstlisting}[style=bashstyle,caption={REP-17: Apelarea finit\_module via ctypes în Python}]
python3 -c "
import ctypes, os
libc = ctypes.CDLL('libc.so.6', use_errno=True)
NR_finit_module = 313
fd = os.open('persist_mod.ko', os.O_RDONLY | os.O_CLOEXEC)
ret = libc.syscall(NR_finit_module, ctypes.c_int(fd), b'', ctypes.c_int(0))
os.close(fd)
"
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{finit\_module} (syscall 313) $\rightarrow$ același contor \texttt{KernelModuleLoad} ca REP-01, dar fără artefact pe disc; combinat cu \texttt{openat} pe fișierul \texttt{.ko} $\rightarrow$ scor $\approx 90$ $\rightarrow$ FREEZE.}

\par \textbf{REP-18 (Rootkit bazat pe cârlige de sistem --- stil Reptile):} Instaurează un canal de comandă și control invizibil rețelei, interceptând apelul de sistem \texttt{kill} pentru a asculta semnale UNIX magice (ex. semnalul 64 pentru a acorda drepturi de root):

\begin{lstlisting}[style=cstyle,caption={REP-18: Interceptarea semnalelor UNIX (stil Reptile)}]
#define SIGNAL_HIDE_MODULE  31
#define SIGNAL_HIDE_PROCESS 63
#define SIGNAL_GET_ROOT     64

static int kprobe_kill_pre(struct kprobe *p, struct pt_regs *regs) {
    int sig = (int)regs->si;
    switch (sig) {
    case SIGNAL_GET_ROOT:
        pr_warn("Tentativa de escaladare la root [blocat]"); break;
    case SIGNAL_HIDE_PROCESS:
        pr_warn("Tentativa de ascundere proces din /proc [blocat]"); break;
    }
    return 0;
}
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{init\_module} la instalarea modulului $\rightarrow$ \texttt{KernelModuleLoad} $\uparrow$; odată rezident, modulul interceptează intern \texttt{kill} --- kprobe-ul Sentinel pe \texttt{kill} detectează semnalele cu valori $>$ 31 emise din procese neprivilegiate $\rightarrow$ scor $\approx 85$ $\rightarrow$ FREEZE.}

\subsection{Injectarea de procese și manipularea memoriei}
\label{subsec:attack_injection}

\par Această clasă de atacuri ocolește mecanismele antivirus prin rularea codului malițios direct în spațiul de adresare al unor procese legitime, exploatând prevalent apelul \texttt{ptrace}.

\par \textbf{REP-11 (Injecție clasică prin \texttt{ptrace}):} Simulează tehnica tradițională în care un proces malițios se atașează de o victimă pentru a-i altera execuția:

\begin{lstlisting}[style=cstyle,caption={REP-11: Atașarea la un proces vizat prin ptrace}]
printf("PTRACE_ATTACH la PID %d -- declanseaza kprobe nr 101\n", target);
if (ptrace(PTRACE_ATTACH, target, NULL, NULL) == -1) {
    perror("ptrace ATTACH a esuat (kprobe a fost totusi declansat)");
    return 0;
}
waitpid(target, &status, 0);
ptrace(PTRACE_GETREGS, target, NULL, &regs);
ptrace(PTRACE_DETACH,  target, NULL, NULL);
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{ptrace} (syscall 101) cu \texttt{PTRACE\_ATTACH} $\rightarrow$ contor \texttt{ProcessInjection} $\uparrow$ $\rightarrow$ scor $\approx 75$ $\rightarrow$ FREEZE.}

\par \textbf{REP-14 (Process Hollowing / RunPE):} Atacatorul lansează un proces legitim, îl suspendă, îi golește conținutul și alocă o nouă zonă de memorie pentru a plasa codul malițios:

\begin{lstlisting}[style=cstyle,caption={REP-14: Etapele de golire a procesului (Process Hollowing)}]
/* Etapa 1: Crearea victimei */
pid_t victim = fork();
if (victim == 0) { for(;;) pause(); }

/* Etapa 2: Atasarea prin ptrace */
ptrace(PTRACE_ATTACH, victim, NULL, NULL);
waitpid(victim, &status, 0);

/* Etapa 3: Alocarea bufferului RWX */
void *inject_buf = mmap(NULL, 4096,
    PROT_READ | PROT_WRITE | PROT_EXEC,
    MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
memcpy(inject_buf, payload, sizeof(payload));

/* Etapa 4: Curatare */
ptrace(PTRACE_DETACH, victim, NULL, NULL);
kill(victim, SIGKILL);
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{ptrace} (syscall 101) $\rightarrow$ \texttt{ProcessInjection} $\uparrow$ și \texttt{mmap} anonim cu \texttt{PROT\_EXEC} $\rightarrow$ \texttt{MemoryInjection} $\uparrow$; scorul compus din doi contori $\rightarrow$ $\approx 88$ $\rightarrow$ FREEZE.}

\par \textbf{REP-19 (Rootkit eBPF --- stil TripleCross):} Un atac hibrid care combină socket-uri brute, alocare de memorie invizibilă pe disc și injectare de procese \cite{TripleCross2022}:

\begin{lstlisting}[style=cstyle,caption={REP-19: Lanțul de atac eBPF Rootkit}]
/* Etapa 1: Socket brut pentru C2 */
int raw_sock = socket(AF_PACKET, SOCK_RAW, htons(0x0003));

/* Etapa 2: Alocare BPF fara artefacte pe disc */
int memfd = (int)syscall(SYS_memfd_create, "ebpf_prog", 0);
write(memfd, bpf_nop, sizeof(bpf_nop));

/* Etapa 3: Alocare memorie executabila (JIT output) */
void *jit_buf = mmap(NULL, 4096,
    PROT_READ | PROT_WRITE | PROT_EXEC,
    MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);

/* Etapa 4: Injectie in procesul victima via ptrace */
ptrace(PTRACE_ATTACH, victim, NULL, NULL);
\end{lstlisting}
\par\textit{Sentinel interceptează 4 contori simultan: \texttt{socket(AF\_PACKET)} $\rightarrow$ \texttt{NetworkAnomaly}; \texttt{memfd\_create} și \texttt{mmap(RWX)} $\rightarrow$ \texttt{MemoryInjection} (de două ori); \texttt{ptrace} $\rightarrow$ \texttt{ProcessInjection} $\rightarrow$ scor $\approx 95$ $\rightarrow$ FREEZE.}

\par \textbf{REP-20 (Furt de memorie în stil LSASS):} Atacul citește memoria procesului țintă pentru a extrage credențiale în clar, folosind pseudo-fișierul de memorie \cite{Bundles2021}:

\begin{lstlisting}[style=cstyle,caption={REP-20: Extragerea credențialelor din memorie via /proc/pid/mem}]
ptrace(PTRACE_ATTACH, victim, NULL, NULL);
waitpid(victim, &st, 0);

char mem_path[64];
snprintf(mem_path, sizeof(mem_path), "/proc/%d/mem", victim);
int memfd = open(mem_path, O_RDONLY);
ssize_t n = pread(memfd, dump, sizeof(dump)-1, (off_t)rstart);
close(memfd);

ptrace(PTRACE_DETACH, victim, NULL, NULL);
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{ptrace} $\rightarrow$ \texttt{ProcessInjection} $\uparrow$ și \texttt{openat(\textquotedbl/proc/\textless pid\textgreater/mem\textquotedbl)} $\rightarrow$ \texttt{LSMFileWrite} $\uparrow$; combinație unică în activitatea legitimă $\rightarrow$ scor $\approx 85$ $\rightarrow$ FREEZE.}

\subsection{Evaziunea defensivă: execuție \textit{fileless} și memorie RWX}
\label{subsec:attack_fileless}

\par Atacurile din această categorie evită interacțiunea cu sistemul de stocare, executând cod exclusiv în memoria RAM.

\par \textbf{REP-07 (Injecție de shellcode în memorie RWX):} Alocă memorie simultan lizibilă, scriptibilă și executabilă, semnătura primară a malware-ului în memorie:

\begin{lstlisting}[style=cstyle,caption={REP-07: Alocare și execuție shellcode în memorie RWX}]
void *region = mmap(NULL, 4096,
    PROT_READ | PROT_WRITE | PROT_EXEC,
    MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);

/* Sled NOP finalizat cu RET (payload inofensiv) */
unsigned char nop_sled[] = { 0x90, 0x90, 0x90, 0xC3 };
memcpy(region, nop_sled, sizeof(nop_sled));

mprotect(region, 4096, PROT_READ | PROT_EXEC);
((void(*)(void))region)();
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{mmap} anonim cu \texttt{PROT\_EXEC} $\rightarrow$ \texttt{MemoryInjection} $\uparrow$ și \texttt{mprotect} pe regiune anonimă cu \texttt{PROT\_EXEC} $\rightarrow$ al doilea increment \texttt{MemoryInjection} $\rightarrow$ scor $\approx 45$ $\rightarrow$ WARN.}

\par \textbf{REP-13 (Execuție fileless prin \texttt{memfd\_create}):} Lansează în execuție un binar ELF complet direct din memorie, fără ca executabilul să persiste pe disc \cite{Elastic2022}:

\begin{lstlisting}[style=cstyle,caption={REP-13: Lanțul de execuție fileless via memfd\_create}]
int memfd = (int)syscall(SYS_memfd_create, "sentinel_payload", 0);
write(memfd, PAYLOAD_ELF, sizeof(PAYLOAD_ELF));

char fd_path[64];
snprintf(fd_path, sizeof(fd_path), "/proc/self/fd/%d", memfd);
char *argv[] = { fd_path, NULL };
execve(fd_path, argv, NULL); /* ELF ruleaza integral in memorie */
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{memfd\_create} (syscall 319) $\rightarrow$ \texttt{MemoryInjection} $\uparrow$ și \texttt{execve} cu cale \texttt{/proc/self/fd/N} $\rightarrow$ pattern \textit{fileless} recunoscut $\rightarrow$ scor $\approx 40$ $\rightarrow$ WARN.}

\subsection{Anomalii de rețea, exfiltrare și C2}
\label{subsec:attack_network}

\par Această categorie testează detectarea comportamentelor atipice prin rețea, caracteristice canalelor de comandă și control.

\par \textbf{REP-04 / REP-12 (Exfiltrare Netcat / Brute-force SSH):} Simulează rafale de apeluri \texttt{socket} și \texttt{connect} spre un host extern sau \texttt{localhost}:

\begin{lstlisting}[style=cstyle,caption={REP-04 / REP-12: Rafală de conexiuni TCP anormale}]
#define TARGET_IP   "127.0.0.1"
#define TARGET_PORT 22
#define BURST_N     20

for (int i = 0; i < BURST_N; i++) {
    int fd = socket(AF_INET, SOCK_STREAM | SOCK_NONBLOCK, 0);
    if (fd < 0) { perror("socket"); continue; }
    connect(fd, (struct sockaddr *)&dst, sizeof(dst));
    close(fd);
}
\end{lstlisting}
\par\textit{Sentinel interceptează rafala de \texttt{socket} + \texttt{connect} (syscall-urile 41, 42); $\geq$ 10 perechi în fereastra de timp $\rightarrow$ contor \texttt{NetworkAnomaly} $\uparrow$ $\rightarrow$ scor $\approx 70$ $\rightarrow$ THROTTLE.}

\par \textbf{REP-15 (Reverse Shell):} Combină activitatea de rețea cu anomaliile de execuție a shell-urilor, reproducând comportamentul unui implant de tip Meterpreter:

\begin{lstlisting}[style=cstyle,caption={REP-15: Conexiune C2 urmată de instanțierea unui shell}]
/* Bucla de conectare (similar comportamentului Meterpreter) */
for (int i = 0; i < ATTEMPTS; i++) { /* socket + connect */ }

/* Executia shell-ului care primeste I/O prin socket-ul de retea */
char *argv[] = { "/bin/echo", "[REP-15] Shell inofensiv...", NULL };
execve("/bin/echo", argv, NULL);
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{socket} + \texttt{connect} $\rightarrow$ \texttt{NetworkAnomaly} $\uparrow$, apoi \texttt{execve} din procesul cu socket activ $\rightarrow$ \texttt{ExecAnomaly} $\uparrow$; combinația rețea + exec $\rightarrow$ scor $\approx 80$ $\rightarrow$ THROTTLE/ISOLATE.}

\subsection{Escaladarea privilegiilor și evadarea din medii izolate}
\label{subsec:attack_privesc}

\par Această categorie vizează depășirea restricțiilor contului curent prin exploatarea binarelor SUID sau evadarea din containere.

\par \textbf{REP-02 (Escaladare de privilegii tip PwnKit):} Încearcă forțarea permisiunilor de root și a capabilităților POSIX, reproducând profilul de syscall al CVE-2021-4034 \cite{PwnKit2022}:

\begin{lstlisting}[style=cstyle,caption={REP-02: Tentative eșuate dar interceptate de setuid și capset}]
if (setuid(0) == -1)
    printf("setuid(0) esuat: EPERM (asteptat) - kprobe declansat\n");

struct __user_cap_header_struct hdr = {
    .version = _LINUX_CAPABILITY_VERSION_3, .pid = 0
};
struct __user_cap_data_struct data[2] = {};
if (syscall(SYS_capset, &hdr, data) == -1)
    printf("capset esuat: EPERM (asteptat) - kprobe declansat\n");
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{setuid(0)} (syscall 105) și \texttt{capset} (syscall 126) $\rightarrow$ contor \texttt{PrivilegeEscalation} $\uparrow$ la fiecare apel, indiferent de rezultatul \texttt{EPERM} $\rightarrow$ scor $\approx 80$ $\rightarrow$ ISOLATE.}

\par \textbf{REP-21 (Detectarea VM și evadarea prin namespace-uri):} Detectează mediul de execuție și forțează asocierea la structurile gazdei prin pivotarea namespace-urilor:

\begin{lstlisting}[style=cstyle,caption={REP-21: Evadarea din container via namespace pivot}]
/* Etapa 1: Detectare hypervisor prin CPUID (asamblor inline) */

/* Etapa 2: Evadarea din container */
chroot("/proc/1/root");

int pidns_fd = open("/proc/1/ns/pid", O_RDONLY);
setns(pidns_fd, CLONE_NEWPID); /* Pivot in namespace-ul PID al gazdei */

int mntns_fd = open("/proc/1/ns/mnt", O_RDONLY);
setns(mntns_fd, CLONE_NEWNS);  /* Pivot in namespace-ul mount al gazdei */
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{openat(\textquotedbl/proc/1/ns/...\textquotedbl)} $\rightarrow$ \texttt{PrivilegeEscalation} $\uparrow$ și \texttt{setns} (syscall 308) $\rightarrow$ al doilea increment; \texttt{chroot} la \texttt{/proc/1/root} semnalează tentativa de evadare $\rightarrow$ scor $\approx 90$ $\rightarrow$ ISOLATE.}

\subsection{Manipularea fișierelor, persistență și recoltare}
\label{subsec:attack_files}

\par Tehnicile din această categorie abuzează sistemul de fișiere pentru a ascunde urmele atacului sau pentru a menține persistența.

\par \textbf{REP-08 (Alterarea fișierelor de jurnal / Log Tampering):} Utilizează \texttt{truncate} și \texttt{unlinkat} pentru a șterge urmele auditelor:

\begin{lstlisting}[style=bashstyle,caption={REP-08: Alterarea fișierelor log în Bash}]
truncate -s 0  /var/log/auth.log
rm -f          /var/log/syslog
mv             /var/log/kern.log /var/log/kern.log.bak
echo "tampered" >> /var/log/dpkg.log
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{truncate}/\texttt{unlinkat} pe căi \texttt{/var/log/*} $\rightarrow$ contor \texttt{LSMFileWrite} $\uparrow$ pentru fiecare fișier de jurnal modificat $\rightarrow$ scor $\approx 50$ $\rightarrow$ WARN.}

\par \textbf{REP-09 (Deturnarea bibliotecilor / LD\_PRELOAD Hijack):} Interceptează dinamic apelurile de bibliotecă legitime prin pre-încărcarea unei biblioteci partajate malițioase:

\begin{lstlisting}[style=cstyle,caption={REP-09: Bibliotecă malițioasă pre-încărcată via LD\_PRELOAD}]
int open(const char *pathname, int flags, ...) {
    static int (*real_open)(const char *, int, ...) = NULL;
    if (!real_open) real_open = dlsym(RTLD_NEXT, "open");
    fprintf(stderr, "[fake_lib] open interceptat: %s\n", pathname);
    va_list args; va_start(args, flags);
    int mode = va_arg(args, int); va_end(args);
    return real_open(pathname, flags, mode);
}

__attribute__((constructor)) void init(void) {
    fprintf(stderr, "[fake_lib] INCARCAT prin LD_PRELOAD\n");
}
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{openat} pe căile interceptate de bibliotecă $\rightarrow$ \texttt{LSMFileWrite} $\uparrow$; prezența \texttt{LD\_PRELOAD} în mediu este semnalată prin \texttt{execve} cu variabilă de mediu suspectă $\rightarrow$ scor $\approx 50$ $\rightarrow$ WARN.}

\par \textbf{REP-16 (Recoltarea de credențiale):} Deschide iterativ fișiere critice de sistem, reproducând comportamentul unui enumerator de credențiale:

\begin{lstlisting}[style=cstyle,caption={REP-16: Enumerarea fișierelor cu credențiale}]
static const char *TARGETS[] = {
    "/etc/shadow", "/etc/shadow-", "/root/.ssh/id_rsa",
    "/proc/1/mem", "/root/.kube/config", NULL
};
for (int i = 0; TARGETS[i] != NULL; i++) {
    int fd = open(TARGETS[i], O_RDONLY);
    if (fd >= 0) { read(fd, buf, sizeof(buf)-1); close(fd); }
}
\end{lstlisting}
\par\textit{Sentinel interceptează fiecare \texttt{openat} pe căile din lista neagră (\texttt{/etc/shadow}, \texttt{/root/.ssh/id\_rsa} etc.) $\rightarrow$ \texttt{LSMFileWrite} $\uparrow$ repetat; 5+ accese în rafală $\rightarrow$ scor $\approx 65$ $\rightarrow$ WARN/THROTTLE.}

\subsection{Anomalii de execuție și epuizarea resurselor}
\label{subsec:attack_exec}

\par Această categorie acoperă abuzarea ierarhiei proceselor și consumul extrem de resurse.

\par \textbf{REP-05 (Webshell Lineage):} Lansează utilitare interactive (\texttt{bash}, \texttt{whoami}) direct din procese numite după servere web (\texttt{apache2}, \texttt{nginx}), reproducând semnătura unui webshell:

\begin{lstlisting}[style=cstyle,caption={REP-05: Lansarea unui shell de către un worker web}]
/* Binarul este redenumit "apache2-worker" prin argv[0] */
static void shell_cmd(const char *path, char *const argv[]) {
    pid_t pid = fork();
    if (pid == 0)      { execve(path, argv, NULL); _exit(1); }
    else if (pid > 0)  { waitpid(pid, NULL, 0); }
}

int main(void) {
    shell_cmd("/usr/bin/id",  id_args);
    shell_cmd("/bin/cat",     cat_args); /* ex. /etc/passwd */
}
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{execve} cu proces-părinte numit \texttt{apache2}/\texttt{nginx} $\rightarrow$ verifica lineage: server web $\Rightarrow$ shell interactiv $\rightarrow$ contor \texttt{ExecAnomaly} $\uparrow$ $\rightarrow$ scor $\approx 70$ $\rightarrow$ THROTTLE.}

\par \textbf{REP-10 (Fork Bomb / Endpoint DoS):} Generează o rafală de procese efemere pentru a epuiza tabela PID a nucleului sau constrângerile \textit{cgroup}:

\begin{lstlisting}[style=bashstyle,caption={REP-10: Fork Bomb limitat (200 de procese efemere)}]
for i in $(seq 1 200); do
    (exit 0) &   # Fortarea unei avalanse de apeluri 'clone'
done
wait
\end{lstlisting}
\par\textit{Sentinel interceptează \texttt{clone} (syscall 56) $\rightarrow$ contor \texttt{ForkBomb} $\uparrow$ la fiecare copil; $\geq$ 50 de apeluri \texttt{clone}/s $\rightarrow$ pragul de anomalie depășit $\rightarrow$ scor $\approx 75$ $\rightarrow$ ISOLATE via constrângere \texttt{cgroup}.}
